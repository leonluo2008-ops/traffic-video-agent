# 参考件逆向实验 — 阶段复盘与沉淀（2026-08-30）

> 状态：**暂停，等新工作流设计**。v5/v5.1 验证了技术链路可行，但「角色归属判定→人工审核」的流程形态两次失败，需推倒重来。

## 一、项目目标

老赵喷车视频（唐伯虎点秋香二创，全长 212.95s）的声音替换：原片角色干声做参考件 → IndexTTS2.5 克隆生成新台词 → 按原时间轴贴回，实现"原片人物说车评梗"。

## 二、已验证走通的链路（技术层 OK）

1. **干声分离**：demucs htdemucs two-stems（PC GPU，ComfyUI python 环境，surface 无环境需 scp 往返）
2. **参考件提取**：全片 VAD → 定位目标角色开口段 → silenceremove 修剪 + loudnorm 归一 → 参考件
3. **克隆生成**：IndexTTS2.5 ComfyUI API（8188 端口）提交/轮询/拉回，参数见溯源表
4. **时长对齐**：生成时长 ÷ 原句时长锚定 atempo，实测 drift ±0.02s，贴轴精度够
5. **混音贴回**：ffmpeg filter_complex 多输入 adelay，人声+伴奏+保留原声段一次合成

**实证**：v5.1 宁王开头两句（对答常态段参考件）用户验收"是正确的"——参考件选对段，全链路即通。

## 三、发现的核心问题（按严重度）

### P0-1 参考件选段决定成败，且"同人不等于同声"
- 同一人不同状态的干声（喊叫 vs 对答），克隆结果天差地别
- 实证①：对穿肠用"索赔500万"激动段 → 生成 7 句全尖嗓，Gemini 盲听检出；换平稳段 → 7-9/10 相似
- 实证②：宁王用上联喊声段（v5）→ 不像；换对答段（v5.1）→ 前两句对了，但后续句仍翻车
- **规则**：参考件 = 该角色"常态声线"的最长独白，情绪激烈段宁可不选

### P0-2 角色归属自动判定不可靠，人工审核的载体又失败了两次
- Gemini 描述式听感判定**同一段音频前后摇摆**（"厚重老者"→"青年男声"）；判"宁王"的句子 A/B 实测仅 2/10
- 60 句画本式审核表发飞书 → 用户明确"不行"：信息密度过大（60行×时间戳/角色/台词三列），逐句审不动
- **结论**：机器初判+人审方向对，但审核界面形态错——不是表格该长什么样，是「一次压给用户的信息量」该重新设计

### P1-3 素材充足度决定质量上限
- 宁王全片仅 2 处开口：上联段 4.8s（喊）+ 对答段 3.2s（激动），**无平稳常态长段**
- 素材不足时克隆必有妥协：要么接受"喊上联人设"，要么该角色保留原声

### P1-4 时间戳自动标注有漂移
- Gemini 相对时间 + 片偏移换算，长片累积误差明显（P10 出现 215-217s 句，超视频全长 212.95s）
- 时间戳是贴轴的生命线，不能只信听感模型报数

### P2-5 切片策略：30s 硬切必断句
- 硬切把"一名二徒三修车…"劈成两半，上下文丢失、转录错乱
- 正确做法：切缝落在 VAD 自然停顿上（已实现：silencedetect → 缝池 → 贪心打包 8-18s 片，11 片覆盖）

### P2-6 VAD 只见语音密度，不见内容
- 74-104s 的 29s 戏剧过场（配乐+惺惺相惜对喊）被 VAD 判"无语音"漏掉
- 补洞要靠剧情意识或全量送听，VAD 块边界只能当初筛

## 四、可复用经验

| 经验 | 细节 |
|---|---|
| A/B 并排对比是听感金标准 | 描述式分类不稳，"两段是否同一人 X/10"的并排判定两次实测都准（9.8/10 同人 ✓、2/10 不同人 ✓） |
| Windows 远程跑批 | cmd 转义地狱 → 写 .bat 推过去执行；输出 GBK 要 errors=replace 解码 |
| 环境分布 | demucs/IndexTTS2.5 都在 PC（D:\AI-tool），surface 只做编排与合成 |
| 聚鑫 Gemini 听感 | gemini-3.5-flash audio 输入，~8-15s/段，30s 内片段最稳 |
| 画本行业格式（用户提供的 docx） | 角色表置顶 + 【角色名】前缀台词行；有声书靠人工试音定角色——对应本项目"人审角色归属"环节，但载体待重新设计 |
