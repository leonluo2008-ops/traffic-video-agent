## 一、验证成立的部分（可直接进工作流）

### 1. 整链路配方（v3 已端到端跑通）
```
原片音轨 → demucs 分离（人声/伴奏双轨）
        → VAD 句级锚点（silencedetect）
        → 分镜分析（角色/台词/时间戳/处置决策）← ⚠️ 当前薄弱环节
        → LLM 填词（按原句节奏，字数纪律）
        → IndexTTS 2.5 零样本克隆重配（参考音频=原片该角色干声）
        → duration_factor 粗选 → 实测时长 → atempo 一步收口
        → 三层混音（伴奏垫底 + TTS 改句 adelay 摆位 + 原声切片贴回）
        → 合回原画面
```

### 2. demucs 分离（PC GPU）
- 环境：**ComfyUI python**（torch 2.11.0+cu128），`python -m demucs -n htdemucs --two-stems=vocals`
- ⚠️ `vocal-sep-server` 独立 venv 的 demucs.exe **缺 torch 不可用**，别再踩
- 38s 音频 GPU 分离 8.5s；Gemini 盲检：伴奏**零人声残留**、干声音节完整（快速咬字处轻微金属电音感，不影响使用）
- 产物路径：`D:\AI-tool\vocal-sep-server\output\htdemucs\<track>\{vocals,no_vocals}.wav`

### 3. VAD 锚点（ffmpeg silencedetect）
- 句级：`-34dB / d=0.30`（8 块）；细拆长块：`-36dB / d=0.22`（9 块）
- 长块会**粘连多个角色**（块1 8.5s 含 2 角色多句）→ 不能只靠 VAD 定角色

### 4. IndexTTS 2.5（ComfyUI API /prompt 提交）
- `duration_factor` 0.5-2.0（step 0.05）；**max_mel_tokens 上限 1815**（超了 400 Bad Request，响应体含节点校验明细）
- **df 档位与时长呈非线性**（C 句 0.85 与 1.0 几乎同长）——不能靠 df 一次到位
- **两步法实测成立**：df 粗选档 → 生成后 ffprobe 实测 → atempo 一步反算收口
- 收口精度（6 句）：±35ms 内全部收敛（atempo 链式二次修反而越修越歪，**必须从原始 flac 单次计算**）

### 6. 双参考音色（用户认可）
- 宁王句参考 = 上联段干声（17.32-24.44s），华安句参考 = 下联段干声（30.44-38s）——**同一素材内取"该角色专属干声"做零样本参考，音色自动贴角色**
- ⚠️ 参考音频头部如果有非目标角色声音会污染克隆

### 7. 三层混音
- `amix=normalize=0` 防削波；原声切片 `atrim+asetpts+adelay` 贴回原位置
- **摆位一律以 VAD 块实测边界为准**（v1 凭转录预估摆位偏早 2.6s 的教训）
- 短槽（<1s）问题：两字句 TTS 最短约 1s，0.5s 槽放不下 → 相邻槽有间隙时可容忍越界 0.4s，否则须合并槽或改词加长原槽

### 8. 填词纪律（v3 教训）
- 新词字数超出原词 3-5 字 → atempo 被迫 1.26-1.55x 压缩 → 语速发赶（Gemini 盲检两处扣分点）
- **纪律：新词字数 ≤ 原词**，长句宁少勿多；数字串联/对仗结构保持

### 9. 工程坑
- 聚鑫 API：curl 命令行传大 payload 报 "Argument list too long" → 换 python urllib
- ComfyUI /prompt 400 响应体必读（含具体哪个参数超限）
- 中文件名经 scp 到 ComfyUI input 可用（COMBO 列表可枚举确认）
- Gemini 分析脚本里 subprocess/json 记得在每个 execute_code 脚本内重新 import

## 二、未解决的核心问题：说话人界定（本轮最大缺陷）

### 实测错误样本
1. **角色命名漂移**：同一个声音，m1 转录标注"对穿祥"、v2 分镜总表标注"宁王"——Gemini 音频转录对角色名的指称不稳定
2. **块内多角色粘连**：VAD 块1（5.03-13.53s，8.5s）内含 2 个角色多句对白，块级分析无法拆分归属
3. **时间戳漂移**：转录给出的句位与声学实测差 2.6s（v1 下联摆位错误的根因）
4. **收尾归属错**：m3 把"老赵啊，这没你的事了"标给华安/旁白，实为现实层转场台词

### 根因
让 Gemini 音频转录**一步到位**输出"角色+台词+时间戳"——它擅长文本，不擅长声学分离与时间定位。角色界定是声学/视觉问题，不是文本问题。

### 解决思路（供整合工作流时选用）
- **证源拆分**：①声学边界（VAD，无角色信息）②声纹聚类（同段内按 embedding 聚成 speaker ID，客观不猜名）③视觉口型（每块抽帧问 Gemini"画面里谁在张嘴"，电影对话以特写为主，锚定"脸"而非"名"）④文本内容（LLM 用对白逻辑辅助归属）
- 合并规则：**时间起止以①为准、说话人切换以②③为准、角色命名锚定③的画面角色、④只做仲裁**
- 声纹聚类候选：resemblyzer（轻量、无 HF token）或 pyannote 3.1（更标准，需 HF 授权）
