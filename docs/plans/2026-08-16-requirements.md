# traffic-video-agent 需求梳理（2026-08-16 用户澄清版）

> 触发：用户纠正原技术路线（LatentSync 口型重渲染 → indexTTS 音频替换）
> 本文件是需求梳理，不是最终方案。待用户确认后进入技术方案设计。

---

## 一、核心思路（已确认）

**保留影视素材原画面（口型不动），只替换音频。**

```
影视素材片段（如《唐伯虎点秋香》对白）
    ↓ 提取角色音频（音色/节奏/情绪）
    ↓ indexTTS 克隆该角色音色
    ↓ 输入"目标文稿"（课程内容改写后的台词）
    ↓ 生成"音色匹配原角色 + 节奏情绪匹配原片段"的新音频
    ↓ 替换原音频 → 画面口型不变，但"说"的是我们的内容
```

**关键区别**：不需要 GPU 重渲染视频口型（LatentSync 死结），只是音频合成替换，轻量得多。

└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  Stage 2: indexTTS 音频生成                                    │
│  ├─ 提取素材片段角色音频（音色参考）                            │
│  ├─ indexTTS 克隆角色音色 + 时长/情感控制                       │
│  └─ 生成匹配原片段节奏情绪的新音频 → 替换原音频                  │

                              ↓

## 三、两大核心卡点（用户明确）

### 卡点 1：素材检索
从海量影视素材里，快速找到**匹配目标文稿**的视频片段。

### 卡点 2：文稿改写
把原始课程文稿，转成**和素材音频相匹配的音频文稿**。
- 即：让课程内容变成"这个角色会说的话"
- 且**长度/节奏/情绪**要贴合原素材音频，这样 indexTTS 生成后替换才自然

**生产环境真实输入形态（2026-08-16 用户澄清，关键）**：
- 用户给到的**可能是**成片式的角色对答（如"方唐镜/包龙星"一问一答）
- **也可能根本没有对白**——只有录制者最初的**课堂文字稿 / 教学转录稿**
- 甚至可能只有画面，要我们凭空生成匹配的对白文稿
- **核心工段**：把"课堂文字稿"这种非对白文本，改写/重写成**匹配上屏视频的角色对白文稿**（选 B：彻底改写，非原样照搬）

**选 B（2026-08-16 用户拍板）**：彻底改写文稿——保留课程内容原意，但按上屏视频的角色、口吻、时长、节奏重新组织，让角色"说人话"。

### 素材提取工段 — 两类素材模型（2026-08-16 用户补充，关键）
从原始视频提取素材时，**不只要提取"对白画面"，还要保留"画龙点睛的辅助素材画面"**：

**类型 1：对白素材（承载台词）**
- 角色说话/张嘴的画面，用于承载改写后的教学台词
- 如：至尊宝 00:30/00:37/01:02 说话瞬间

**类型 2：氛围辅助素材（画龙点睛，提升质感）**
- 经典桥段 / 提神场景 / 情绪镜头，**不承载教学对白**，但大幅提升视频整体感觉
- 如：大话西游开局至尊宝跳下+紫霞拔剑（00:00-00:22）戏剧对峙，天然适合做**开场提神**
- 用法：开场抓眼球、转场衔接、情绪渲染、高潮配合

**核心原则**：这类经典桥段画面保留下来，对整体视频感觉提升非常好，不应在"只提取对白"时被丢弃。素材提取 = 对白素材 + 氛围辅助素材，两者都要采集。

## 三·A、文稿改写工段 — 通用适配方法论（2026-08-16 用户确认，待验证）

> **定位**：这是通用工具的核心工段，不是大话西游/SP 专用定式。必须能匹配不同素材、不同课程。以下方法论以"大话西游 + SP鱼鳞焊"为测试用例演示，但框架本身通用。

### 本质
把"教学知识点"装进"目标素材的对话场景"，用对话把知识点演绎出来。**内容→形式 的适配**。最高原则：**演绎不违和**——角色会说这种话、时长放得下、情绪匹配画面。

### 双基准点 + 适配

**基准点 1 · 知识层**（来自课程原稿）
- 从原稿提取知识要点，每个要点拆成**最小可演绎单元**
- 每个单元 = 核心信息 + 讲解动作（引入 / 解释 / 演示 / 操作 / 收尾 / 强调）

**基准点 2 · 场景层**（来自目标素材）
- 识别素材的**对话结构**：有哪些角色、谁主导谁反应、角色人设
- 识别每个**说话瞬间**：角色、情绪、时长、镜头

**适配层 · 演绎映射**
把知识单元分配到对话场景上。匹配逻辑：

| 知识单元的讲解动作 | 对话场景的戏剧功能 |
|---|---|
| 引入 / 提问 | 主导角色的"提问 / 发难" |
| 解释 / 演示 | 解答角色的"讲解" |
| 操作 / 步骤 | 解答角色的"示范" |
| 收尾 / 强调 | 反应角色的"确认 / 感慨" |

**角色分工（谁讲解答）**：由目标素材的**故事情节设定**决定——谁在戏里是"懂的人"谁讲解答，谁"求教/发问"谁提问，谁情绪反应多谁做反应/追问。**这是动态的，随素材变，不以任何单一素材为定式。**

### 产出：结构化对白文稿（JSON）
每句台词带：角色 / 音色参考 / 起止秒 / 文本——直接驱动 indexTTS + 画面切分 + 录屏对齐。

```json
{
  "title": "SP鱼鳞焊制作教程（大话西游版）",
  "segments": [
    { "start": 0.5, "end": 4.2, "role": "至尊宝", "voice_ref": "至尊宝音频.mp3",
      "text": "紫霞，SP里面想要做出鱼鳞焊效果，该从何处下手？" },
    { "start": 4.5, "end": 10.5, "role": "紫霞", "voice_ref": "紫霞仙子音频.mp3",
      "text": "这点小事难不倒我。先在材质图层新建普通绘制图层便是。" }
  ]
}
```

### 🧭 情景语境匹配铁律（2026-08-16 用户确认，核心原则）
> **目标台词的情绪语境，必须匹配该画面片段/参考音频的情绪语境。** 这是剧本编排的第一约束，优先于知识点内容。

- 选参考音频片段时，**情绪是硬约束**：一个片段 = 一个独立"情绪 + 音色 + 角色"样本
- 设计目标台词时，**先在"该情绪语境"下想"这角色此刻该说什么话"**，再往话里塞知识点
- **反例（已验证失败）**：悲伤哭腔画面配"这等小事也敢来问我"傲娇台词 → TTS 用悲伤参考念傲娇台词 → 音色变"恶婆婆"（紫霞失败第二重根因）
- **正例**：悲伤关切语境 → 台词用关切提醒语气带出知识点（如"你当真要回去同她们交代……SP 的鱼鳞焊你可学会了？"）
- **推论**：傲娇台词只能配傲娇画面，悲伤台词只能配悲伤画面。**不是每段素材都适合塞知识**——纯感情戏/过渡段（如悲伤落泪）应作情绪过渡或跳过，不强行教学。

### 🧠 智能决策环节（2026-08-16 用户要求，剧本编排核心）
> **剧本编排不是硬编码规则，而是 Agent 的智能决策过程。** 必须有一个"识别 → 匹配 → 编排"的决策环节，随素材变化，不写成定式。

**决策流程（Agent 执行，非固定套路）：**
1. **识别原视频**：用 Gemini 视频分析产出每片段的【角色 + 情绪 + 时长 + 镜头 + 台词】（已有工具链）
2. **对齐知识原稿**：把课程/知识原稿拆成"最小可演绎单元"（每个单元 = 核心信息 + 讲解动作）
3. **匹配编排（智能决策核心）**：Agent 综合判断——
   - 这段画面情绪适合塞什么知识单元？（铁律：情绪语境匹配）
   - 谁主导/谁反应？（由故事情节设定动态决定，非定式）
   - 时长放不放得下？角色会不会说这种话？（不违和）
4. **产出目标台词**：在情绪语境下，让角色自然演绎知识单元
5. **逐段验证**：每段目标台词情绪 ↔ 参考音频情绪是否匹配，不匹配则重排

> ⚠️ **不硬编码测试用例**：当前大话西游 + SP鱼鳞焊只是验证工作流的测试用例，决策逻辑本身必须通用——换素材/换课程，流程不变，只是输入（视频、知识原稿）和识别结果变。

### ✂️ 视频分析标注的第二作用：驱动原视频裁切（2026-08-16 用户补充）
> 视频分析标注不只用于剧本编排，还用于**裁切原视频**。标注产出的每片段【起止时间 + 角色 + 情绪 + 镜头】，是后续视频剪辑的**直接素材清单**。

- 根据标注时间点，用 ffmpeg 裁切原视频为独立片段（按角色/情绪命名）
- 裁切后的片段供剪辑工段直接取用——上屏影视素材"做梗"+ 下屏操作录屏，按片段对齐
- **标注工作至关重要**：既是台词编排的输入，也是视频裁切的依据，一个标注两份用

## 六、已验证成果（2026-08-16）

### ✅ indexTTS-2.5 音色克隆跑通
- PC 部署完成（RTX 5070Ti 16GB），ComfyUI 节点全加载
- **ComfyUI API 批量生成验证通过**：10/10 句对白（至尊宝6+紫霞4）全部成功
- 产物：`ref/成片范例/音色克隆产物/`（10 个 flac + 合并 mp3）

### ✅ 测试一：情景语境匹配验证通过（2026-08-16，用户听音给7/10分）
> **验证目标**：目标台词情绪匹配参考音频情绪 → 解决紫霞音色问题
- **方法**：纯人声悲伤参考（Demucs 分离 BGM）+ 悲伤关切语气目标台词
  - 参考音频：`input/参考音频/紫霞_纯人声悲伤.wav`（5.68s，Demucs 剥离 BGM 后纯人声）
  - 目标台词1："你当真要回去同她们交代？可……这SP鱼鳞焊，你可都学会了？"
  - 目标台词2："我帮你便是……你先莫慌，新建材质图层，一步步来就好。"
- **结果**：2/2 生成成功，用户 ComfyUI 试听满意（**10分给7分，符合70%预期**）
- **结论**：**情绪匹配是紫霞音色问题的解**——悲伤画面配悲伤台词，TTS 不再"恶婆婆"。剩余3分留待后续优化（情绪/采样参数细调）
- 产物：PC `output/test1_zixia_sad/`（2 flac）

### ⚠️ 紫霞克隆失败根因（参考音频不合格）
- 现象：至尊宝音色 OK，紫霞像"恶婆婆"
- **根因**：原`紫霞仙子音频.mp3`（10s）只有 2s 是紫霞（还是愤怒威胁语气），后面 6s 混入至尊宝男声 → 声纹污染
- **官方参数确认**：参考音频最佳 3-10s 干净单人声；自动截断到 15s
- **解决方案**：从原视频提取干净温柔单人紫霞片段作参考（01:29-01:32"你怎么向娘子交代"）
- **架构教训**：参考音频须"情绪匹配目标台词"，且**角色/情绪识别应在文稿改写前运行**（作为台词设计约束），避免"温柔画面配傲娇台词"错位

### ⚠️ 参考音频构造方法（2026-08-16 用户实测确认，关键工作流修正）
> **推翻早期"整块拼接"认知**。用户实测两种方法对比，结论如下：

- ❌ **不可行**：把一个角色的所有音频拼成一条参考音轨去生成——**拼接会破坏情绪纯度，音色效果差**
- ✅ **可行（逐段匹配法）**：
  1. 用原视频里**"情绪+台词+角色"对应的单个音频片段**作参考（一个片段=一个独立情绪+音色样本）
  2. 目标台词必须**匹配该参考片段的情绪**（悲伤参考配悲伤台词）
  3. 参考音频短没关系：角色说话即使只 2 秒，**前后补静音到 3 秒**，达到 IndexTTS 最低参考标准
  4. 只要目标台词得当，**音色比拼接版好**（用户已实测验证）
- **对应成片范例**：成片制作者"拼接+整块生成"的做法，实际效果不佳；应改为逐段匹配生成
- **操作要点**：参考片段从原视频按"情绪片段"提取（可含少量静音补齐 3s），不用强求长片段

### 🎧 人声分离环节（2026-08-16 用户补充，必需环节）
> **参考音频必须纯人声**，剥离 BGM/背景音乐/音效。这是参考音频构造的**前置硬性条件**——带 BGM 的参考会污染音色提取（如紫霞参考带悲伤古风 BGM → 音色被音乐干扰）。

**工作流插入点**：`提取原视频音频 → ⭐人声分离 → 得到纯人声片段 → 按情绪片段切分 → 静音补齐3s → 作参考音频`

**选型（调研确认）**：
- **Demucs**（Meta 开源）——分离质量最高（SDR 领先），`demucs --two-stems vocals`，GPU 加速；PC RTX 5070Ti 可跑
- UVR5（Ultimate Vocal Remover）——GUI 版，核心算法就是 Demucs/MDX；适合人工操作
- Spleeter——快但质量一般，可选
- **推荐**：Demucs（高质量纯人声，适配参考音频需求）
