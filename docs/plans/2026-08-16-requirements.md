## 一、核心思路（已确认）

**保留影视素材原画面（口型不动），只替换音频。**

```
影视素材片段（如《唐伯虎点秋香》对白）
    ↓ 提取角色音频（音色/节奏/情绪）
    ↓ indexTTS 克隆该角色音色
    ↓ 输入"目标文稿"（课程内容改写后的台词）
    ↓ 生成"音色匹配原角色 + 节奏情绪匹配原片段"的新音频
    ↓ 替换原音频 → 画面口型不变，但"说"的是我们的内容
```

**关键区别**：不需要 GPU 重渲染视频口型（LatentSync 死结），只是音频合成替换，轻量得多。

## 二、完整工作流（以文稿时间线为主轴）

```
┌─────────────────────────────────────────────────────────────┐
│  Stage 1: 素材检索 + 目标文稿生成                              │
│  ├─ 从海量影视素材中，找到匹配目标文稿的视频片段（卡点1）        │
│  └─ 把原始课程文稿，改写成"匹配素材音频"的目标文稿（卡点2）      │
│      → 产出：素材片段 + 目标文稿 + 时间轴                       │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  Stage 2: indexTTS 音频生成                                    │
│  ├─ 提取素材片段角色音频（音色参考）                            │
│  ├─ indexTTS 克隆角色音色 + 时长/情感控制                       │
│  └─ 生成匹配原片段节奏情绪的新音频 → 替换原音频                  │
│      → 产出：上屏影视片段（已换音频）                           │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  Stage 3: 人工录制下半段操作视频                                │
│  ├─ 录制人员按"文稿内容时间轴"录制软件操作                      │
│  └─ 产出：原始录屏素材                                         │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  Stage 4: AI 初检                                             │
│  ├─ AI 根据"目标文稿时间轴 + 音频时间轴"对录屏做初检            │
│  ├─ 检查：操作步骤是否对齐、时长是否匹配、有无冗余               │
│  └─ 产出：初检报告 + 修正建议                                   │
└─────────────────────────────────────────────────────────────┘
```

## 三、两大核心卡点（用户明确）

### 卡点 1：素材检索
从海量影视素材里，快速找到**匹配目标文稿**的视频片段。

### 卡点 2：文稿改写
把原始课程文稿，转成**和素材音频相匹配的音频文稿**。
- 即：让课程内容变成"这个角色会说的话"
- 且**长度/节奏/情绪**要贴合原素材音频，这样 indexTTS 生成后替换才自然

## 四、待澄清的关键点

### 1. 素材检索的"匹配标准"是什么？
- 主题关键词匹配？（课程讲"金属氧化"→ 找影视里讲类似话题的）
- 情绪/角色匹配？（找愤怒的、儒雅的）
- 时长匹配？（片段长度 ≈ 目标台词时长）
- 还是组合？

### 2. 目标文稿的"改写程度"？
- 保持课程内容原意，只是用角色音色读出来？
- 还是彻底改写成角色口吻？（让唐伯虎用他的腔调讲"金属氧化怎么做"）

### 3. 素材库现状？
- 现在有多少影视素材？整部剧（三国全集）还是零散片段？
- 有没有标注/索引？

### 4. 上下屏如何合成？
- 上屏影视片段 + 下屏录屏，是最终合成一个视频，还是分开交付给剪辑师？

## 五、技术选型初步判断（待确认）

| 环节 | 候选技术 | 状态 |
|---|---|---|
| 素材检索 | TalkNet-ASD（说话检测）+ DeepFace（情绪）+ 关键词/向量检索 | 待定 |
| 文稿改写 | LLM（DeepSeek/GLM）角色扮演改写 | 待定 |
| 音频生成 | **indexTTS**（B站开源，零样本音色克隆 + 时长/情感控制） | 主选 |
| 录屏初检 | LLM + 音频时间轴对齐 | 待定 |
