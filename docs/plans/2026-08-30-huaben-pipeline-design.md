# 画本流水线设计（v2 — 用户主导工作流）

> 2026-08-30 powerflow Phase 1 产出。用户提出核心工作流，AI 补工具选型与审核形态，用户已拍板。

## 一、工作流六步（用户定义）

1. **音频提取**：原视频 → demucs 人声/伴奏分离（已验证）
2. **原始画本生成**：人声 → 说话人分离+转写+时间戳 →「谁-何时-说了什么」结构化剧本
3. **人工审核①**：声音包命名制（方案 A）→ 得到准确的原始画本
4. **填词画本生成**：原始画本 + 目标创意 → 逐句填词（时间线不乱、角色不乱、字数节奏贴合原句）
5. **人工审核②**：用户审填词画本
6. **克隆合成**：按时间轴用对应角色干声做参考件 → IndexTTS2.5 生成 → 原位替换混音输出

## 二、关键决策记录

| 决策点 | 结论 | 依据 |
|---|---|---|
| 说话人分离工具 | FunASR（阿里达摩院） | 中文最优（Paraformer+CAM++），一次输出谁-何时-说什么；本地免费；Gemini 听感两次证伪（角色摇摆+时间戳漂移） |
| 执行环境 | PC（RTX 5070 Ti 16GB, torch 2.11+cu128, modelscope 1.39.1 已装） | 环境探测 2026-08-30，仅缺 funasr 包 |
| 审核①形态 | 方案 A 声音包命名制 | 用户拍板。每聚类发 10s 代表音频，用户命名 5 次 + 抽查 5-8 句，替代 60 行表格 |
| Gemini 角色 | 降级为抽检员 | 描述式判定不可靠，A/B 并排对比仍可用 |

## 三、方案 A 审核界面细节

- FunASR 输出 SPEAKER_00/01/02… 聚类 → 每聚类拼 10s 代表音频（Feishu 语音条）+ 该聚类句子清单（低密度）
- 用户回复格式：`00=宁王 01=对穿肠 ...`
- 存疑句抽查：FunASR 置信度低/聚类边界句 → 单独列 5-8 句让用户确认归属
- 命名完成 → 全片画本自动带角色名 → 进入填词阶段

## 四、与旧流程的区别（为什么更好）

- 旧：机器逐句判角色（不可靠）→ 60 行表格一次压给用户（审不动）
- 新：声纹聚类（确定性算法）→ 用户只做 5 次命名 + 少量抽查（决策量降 80%+）
- 时间戳从"听感估读"变为"对齐算法输出"，漂移问题根治

## 五、待决问题（后续拍板项，不阻塞 FunASR 测试）

1. 填词画本的新台词起草权（AI 起草人审 vs 用户给词）
2. 素材不足角色（宁王仅 8s 干声）的处置：接受妥协克隆 vs 保留原声
3. 填词字数/节奏约束的量化标准（对标原句时长 ±15%？）

## 六、测试验收标准（本阶段）

- FunASR 在 PC 上跑通全片 diarization，输出含：说话人聚类数、每句起止时间、转写文本
- 聚类数与已知角色数（约 5-6 个）一致 ±1
- 抽 3 句与 Gemini 旧判读交叉对比，时间戳差 < 0.5s
