# traffic-video-agent 设计文档

> 2026-08-10 · Phase 1 Brainstorm 产出 · 待用户审批后进入 Phase 2

## 样片分析

参考样片：抖音"建模老陈"3D贴图教程（Substance Painter 回火痕迹）

**视频形式**：竖屏 9:16 上下分屏
- 上屏 1/3：影视剧片段（角色对话做"梗"吸引注意力）
- 下屏 2/3：软件操作录屏

**核心要素**：
- 旁白：TTS 声音克隆，角色扮演（提问者+回答者）
- 剪辑：2-3秒切换一次，前7秒高能量开场
- 字幕：居中偏上，黄色关键词标注
- 视觉引导：红色圆圈标注软件按钮

## 用户需求（5 点反馈）

1. 文案由 LLM 生成（无争议）
2. TTS 由人工用 MiniMax 网页版生成（后期商用接 API）
3. 软件录屏人工完成，但需要 AI 辅助粗剪
4. 影视素材 AI 辅助筛选+口型匹配（核心难点）
5. 最终输出一套方便人工剪辑师快速组装的素材包

## 工作流设计

```
输入物料              AI 加工层                    交付给剪辑师
─────────────────────────────────────────────────────────────────

① 知识点/主题 ──→ [Stage 1: 脚本生成] ──→ 对答式脚本.json
                   (LLM 角色扮演)              (含角色台词+情绪标记)

② TTS 音频     ────────────────────────→ 音频文件.wav
                   (人工 MiniMax 网页版)       (分角色多段)

③ 软件录屏     ──→ [Stage 2: 录屏粗剪] ──→ 粗剪录屏片段/
   (人工录制)       (Auto-Editor +                + 操作清单.json
                    PySceneDetect)               (每个片段=一个操作步骤)

④ 影视素材     ──→ [Stage 3: 素材筛选] ──→ 推荐素材清单.json
   (一堆未处理)     (TalkNet-ASD +                (含时间码+情绪标签+
                    DeepFace +                    口型匹配评分+
                    SyncNet)                      推荐理由)

                   [Stage 4: 剪辑工程生成]

⑤ 以上所有 ────→ [Stage 4] ─────────────→ 剪辑素材包/
                   (OTIO + ffmpeg)              ├── project.otio (Premiere/FCP/Resolve 可导入)
                                                ├── project.edl  (通用 EDL 格式)
                                                ├── audio/       (TTS 音频+参考轨)
                                                ├── video/       (推荐影视片段+录屏片段)
                                                ├── subtitles/   (SRT 字幕)
                                                └── README.md    (剪辑指引)
```

### Stage 1: 脚本生成（LLM）

**输入**：知识点/操作主题（如"SP 中如何做金属氧化回火痕迹"）
**输出**：对答式脚本 JSON

```json
{
  "title": "金属回火痕迹",
  "characters": [
    {"name": "提问者", "emotion": "急切好奇", "tts_voice": "粗犷男声"},
    {"name": "回答者", "emotion": "儒雅自信", "tts_voice": "儒雅男声"}
  ],
  "scenes": [
    {
      "id": 1,
      "type": "opening",
      "speaker": "提问者",
      "emotion": "愤怒急切",
      "line": "金属受高温产生的氧化回火痕迹，在SP当中如何快速做出来？",
      "screen_action": "展示最终效果",
      "duration_estimate": "5-7s"
    },
    {
      "id": 2,
      "type": "teaching",
      "speaker": "回答者",
      "emotion": "恭敬平和",
      "line": "主公稍听臣细说，步骤并不繁杂。首先我们先准备一个金属材质。",
      "screen_action": "新建填充图层",
      "duration_estimate": "6-8s"
    }
  ]
}
```

**LLM 角色**：DeepSeek（tr-writer provider，与 course-builder 共用）

### Stage 2: 录屏粗剪（AI 辅助）

**输入**：人工录制的软件操作视频（通常很长，含思考、犹豫、重复）
**输出**：粗剪后的片段目录 + 操作清单 JSON

**技术路线**：
1. **Auto-Editor**：根据音频静音段自动删除冗余（思考时的沉默、犹豫），保留有语音对应的录屏段
2. **PySceneDetect**：在 Auto-Editor 保留的段内做场景检测，按操作步骤切分
3. **FFmpeg**：按切分点导出独立片段

```bash
# Auto-Editor 粗剪（删除静默段，保留有动作的部分）
auto-editor raw_recording.mp4 --edit audio --margin 0.2sec --export premiere

# PySceneDetect 场景检测（在粗剪后的视频上做操作步骤切分）
scenedetect -i cleaned.mp4 detect-content -o scenes/ split-video
```

**输出 JSON**：
```json
{
  "source": "raw_recording.mp4",
  "cleaned_duration": "180s（原始 600s）",
  "clips": [
    {"id": "clip_01", "file": "scenes/clip_01.mp4", "time": "0:00-0:15", "action": "新建填充图层"},
    {"id": "clip_02", "file": "scenes/clip_02.mp4", "time": "0:15-0:32", "action": "关闭所有通道"}
  ]
}
clips 的 action 标注需要 LLM 配合（截关键帧 → Gemini 识别操作内容）
```

### Stage 3: 影视素材筛选（核心难点）

**输入**：一堆未处理的影视剧视频 + Stage 1 的脚本 + Stage 2 的 TTS 音频
**输出**：推荐素材清单 JSON（每个脚本场景推荐 3-5 个候选片段）

**技术路线（三层过滤）**：

```
原始素材（如三国全集）
    ↓ PySceneDetect（场景切分）
    ↓ TalkNet-ASD（筛选"人在说话"的片段）
    ↓ DeepFace（识别表情情绪，匹配脚本中的角色情绪）
    ↓ SyncNet（口型活动度评分，匹配 TTS 音频节奏）
    ↓ LLM 综合评分+排序
推荐片段清单
```

**Layer 1 — 场景切分**：PySceneDetect 将整集剧切成独立镜头
**Layer 2 — 说话检测**：TalkNet-ASD 从镜头中筛出"有角色在说话"的片段，输出说话时间段 JSON
**Layer 3 — 表情/情绪识别**：DeepFace 对每个说话片段做表情识别（愤怒/平静/惊讶/轻蔑等），匹配脚本中的情绪标记
**Layer 4 — 口型匹配评分**：SyncNet 计算每个候选片段与 TTS 音频段的口型同步评分
**Layer 5 — LLM 综合排序**：把以上数据喂给 LLM，让它根据"情绪匹配度+口型评分+画面衔接流畅度"综合排序

**输出 JSON**：
```json
{
  "scene_id": 1,
  "speaker": "提问者",
  "emotion": "愤怒急切",
  "audio_segment": "audio/scene_01.wav",
  "candidates": [
    {
      "source": "三国_EP12.mp4",
      "time_range": "00:15:32-00:15:39",
      "duration": "7s",
      "emotion_detected": "anger",
      "emotion_match": 0.92,
      "lip_sync_score": 0.78,
      "speaking_confidence": 0.95,
      "overall_score": 0.85,
      "recommend_reason": "曹操拍案表情与'愤怒急切'高度匹配，说话节奏与音频吻合"
    }
  ]
}
```

### Stage 4: 剪辑工程生成（OTIO）

**输入**：Stage 1-3 的所有 JSON + 媒体文件
**输出**：完整的剪辑素材包，剪辑师导入即可工作

**技术路线**：用 OpenTimelineIO 生成跨平台剪辑工程文件

```
delivery/
├── project.otio              # OTIO 工程（可转 Premiere/FCP/Resolve/剪映）
├── project.edl               # EDL 备用格式
├── audio/                    # TTS 音频（分轨）
│   ├── scene_01_q.wav
│   ├── scene_01_a.wav
│   └── ...
├── video/
│   ├── footage/              # 推荐影视片段（已按推荐截取）
│   │   ├── scene_01_candidate_01.mp4
│   │   └── ...
│   └── screen/               # 粗剪录屏片段
│       ├── clip_01.mp4
│       └── ...
├── subtitles/
│   └── full_subtitle.srt     # 完整字幕
├── editing_guide.md          # 剪辑指引（LLM 生成）
└── manifest.json             # 素材清单+映射关系
```

## 技术成熟度评估

| 环节 | 自动化程度 | 人工参与 | 技术风险 |
|---|---|---|--- |
| Stage 1 脚本生成 | 全自动 | 审核修改 | 低 |
| Stage 2 录屏粗剪 | 90%自动 | 检查切分点 | 低 |
| Stage 3 素材筛选 | 70%自动 | 最终选择+微调 | **中** — SyncNet 评分准确度需验证 |
| Stage 4 工程生成 | 全自动 | 导入后微调 | 低 |

**最大风险**：Stage 3 Layer 4 的 SyncNet 口型匹配——原始 SyncNet 是用于评估 lip-sync 质量的学术工具，我们需要的"从素材库中找最佳匹配"的用法需要包装适配。**如果效果不理想，降级方案是只做 Layer 1-3（情绪+说话检测），口型对齐交给人工。**

```
traffic-video-agent/
├── src/
│   ├── core/                 # ← 复用 course-builder call_llm_step.py 框架
│   │   ├── call_llm.py       # 精简版 LLM 调用（从 course-builder 提取）
│   │   ├── project.py        # 项目管理（参考 course-builder 但独立实现）
│   │   └── providers.json    # 复用 course-builder 的 provider 配置格式
│   ├── stage1_script.py      # 脚本生成
│   ├── stage2_screencast.py  # 录屏粗剪（Auto-Editor + PySceneDetect）
│   ├── stage3_footage.py     # 影视素材筛选（TalkNet + DeepFace + SyncNet）
│   ├── stage4_delivery.py    # 剪辑素材包生成（OTIO）
│   └── utils/
│       ├── ffmpeg_helper.py  # FFmpeg 工具函数
│       └── audio_helper.py   # 音频处理（Whisper 字幕）
├── providers.json            # provider 配置（与 course-builder 共用格式）
├── .env                      # API keys（与 course-builder 共用）
├── projects/                 # 产出数据（gitignore）
└── templates/                # 项目模板
```

**复用方式**：不从 course-builder import（它是个 skill 不是 package），而是提取核心模式（call_llm_step 的 OpenAI 兼容调用方式、providers.json 格式、project.py 目录管理思路）在本项目独立实现。
